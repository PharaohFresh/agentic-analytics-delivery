# Model and role selection

Roles identify responsibility; they do not mandate a model tier. Choose a capable available session model for research, planning, implementation choices, synthesis and final verification. Delegate a bounded task when it improves speed, coverage or independence, and brief it with scope, evidence, file ownership and acceptance criteria.

The root remains accountable. It reads decisive code, source passages, arithmetic and visual evidence directly when the conclusion depends on them. A summary from another agent is an input to judgment, not a substitute for verification.

Use a fresh-context reviewer before consequential external delivery or live mutation and when independent challenge improves difficult reasoning. Deterministic counts, hashes and tests verify mechanical behavior; another model is useful for judgment and challenge.

Escalate missing authority, material tradeoffs, conflicting evidence and changes to risk or scope. Recover stalled work by narrowing, advising or taking it over. Models can propose changes, but cannot waive approval, privacy, capital or production boundaries.

The local demonstration does not invoke a model and has no measured model-cost comparison. Any deployment that uses multiple model tiers should measure quality, total cost and recovery overhead rather than assume that lower-cost workers are adequate or that a tier split guarantees savings.
